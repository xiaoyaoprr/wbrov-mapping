这次首次中断的链条为存储长停顿、队列耗尽、采集空档、门控暂停；之后还存在真实跟踪丢失，不能把每次切链都说成同一原因。暂停前主图只有一个参考节点，也不足以完成当前三候选纯视觉合并。完整保存已采帧不代表没有漏掉真实时间中的图像。

## 离线与失败记录的解释

- candidate1/2/3：构建及原生回归记录。candidate3 相机 16 项 CTest 通过，门控和质量回归通过；最终 v2 入口 32 项 Python 检查通过。
- validation1：原生 visual 测试环境遗漏 private trace 目录而失败；validation2 补齐后通过。第一轮失败保留。
- validation1/2 的无 Tag 录像均保留恢复失败；不能用同一录像开 Tag 后的成功替代。
- validation2、validation3 中命名为 baseline 的写盘试验误用了候选头文件，**不是基线**，不得用来证明收益。
- baseline4：源码来源断言失败，未运行。baseline5 用精确 camera6 构建来源，依赖路径已核对，才是有效对照。
- 固定比较 baseline5/paced_baseline_stall 与 validation3/paced_candidate_stall：同一输入、一次 14 秒注入，旧版最大追加 11,527.9 ms，候选 3.94838 ms；两边 1,581 帧全部逐字节一致。该合成测试通过，真实长时并发仍失败，未重复挑选成功结果。
- 实机第一次 `round6_field_notags` 因空 Tag 参数被解析成当前目录而启动失败；修复参数传递后才做 v2。两次原始结果均保留。
- 第一次保存审计因后台未关闭被入口断言拒绝，未读取活动数据库；本目录 audit 是真正关闭后的一次完整审计。

完整输入、SVO、数据库和点云仅在设备与用户指定电脑备份中；本目录提供文本证据及截图，不上传大录像/数据库。`evidence_sha256.json` 核对收集时的远端原始文件；仓库 `MANIFEST.sha256` 另核对本目录全部公开文件。
