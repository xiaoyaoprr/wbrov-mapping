# 可用建图验收（进行中）

本轮先接通可用建图。用户离场后明确要求继续离线优化，待次日再做实机验收。Core v5 保持不变，候选 worker v30 只调整记录解码与显示缓存；保留逐帧处理与写图质量门槛。旧地图定位、路径规划和自主运动不在本轮验收范围内，8 号尚未更新。

## 已有证据

- `v26/`：此前现场录像的完整回放。10,746 帧、397.832 秒输入，519.658 秒完成；一次恢复后继续增加主图节点，数据库关闭检查及点云重组对照通过。回放不能替代新入口实机验收。
- `failed_hardware1/`：首次真实相机测试失败。RGB-D 写盘队列达到容量上限，采集退出并触发关灯。原生处理记录中出现两次恢复，但入口随后停止了处理队列，未正常关闭数据库，不能算保存成功。原始录像和 RGB-D 输入留在 Jetson。
- `failed_hardware2/`：第二次采集超时退出后的保存审计。367 个封存段、10,059 帧全部处理，时间戳逐一对应；490 个主图节点、473,595 点，数据库 `quick_check=ok`、保存文件哈希一致。最终处于恢复观察中，恢复计数为零，明确不是断图恢复验收成功。`complete=false`、`partial_saved=true`。
- `failed_continuity_hardware3/`：第三次静止相机测试。8,388 帧全部处理，SVO 校验、正常保存和所有子进程退出通过；但发生 40 次源时间缺口切链和一次初始质量切链，主图只有 1 节点、8,034 点。这是正常保存通过、持续采集失败的证据。

## 当前问题及候选修复

第二次实机已显示点云、Tag、历史轨迹和红 X／绿 Y／蓝 Z 三轴位姿。运行约七分钟后，采集因 `RGB-D spool: recording writer backpressure timeout` 退出。灯自动关闭、RGB 停在最后一帧是这一退出链路的结果；未证实 RViz 崩溃，亦未证实点云密度是写盘阻塞的直接原因。

第二版入口对已关闭但非正常结束的采集保留后台处理，等待所有封存段处理完成，再将其明确标为“中断后保存”，不冒充完整录像验收。该次最终结果另附回执。

第二次运行的点云重组／导出累计约 1,606 秒，整轮约 2,079 秒；128 MiB 相机点缓存反复重建。它证明较大地图下存在明显处理负担，但没有给出采集写盘卡顿的直接因果证据。操作者也观察到地图变形，尚未完成有已知尺寸或真值的几何精度检验。

第三版候选保留 64 帧队列上限，满时等待写盘腾出空间；不丢弃已接受的帧，不把单纯等待十秒认定为写入失败。真实写入错误仍会结束采集并保留输入。增加封存阶段计时和界面“采集/写盘等待”提示。慢存储仍可能使实时 RGB 暂停，不能据此宣称实时性问题已解决。

第三次实测明确捕获到 `data_sync_ms=29124.8` 和生产者 `wait_ms=27927.1`，共有 83 个源时间间隔超过 300 ms；此时只有 8,034 点，不能归因于大点云渲染。存储同步直接阻塞采集已有证据，SSD 内部回收、温度等物理成因尚未证明。发现问题后请求正常保存退出，RViz 随入口正常关闭，退出码为 0。

## 离线优化候选（实机待验）

- RGB-D 封存采用 Zstandard level 1，并按字节重排 float32 深度。恢复时逐字节逆变换，不量化深度，不改时间戳，不删帧；兼容旧格式。维持原有封存同步与完成回执要求。
- 10,746 帧完整录像的往返检查通过：原始段合计 14,191,911,957 字节，压缩段估算合计 9,078,777,379 字节，减少约 36.0%。包含颜色、深度、IMU、内参和纳秒时间戳的记录逐字节一致。
- 相机点采样缓存由 128 MiB 调整为有界的 512 MiB 常驻集合；避免整图循环遍历时 LRU 逐个淘汰下一轮即将读取的节点。不改变图约束、体素分辨率或点云输出规则。
- 原生相机编译及 12 项测试通过。压缩格式短录像、完整录像和大地图共 22,386 帧全部处理，逐帧时间戳一致，数据库与点云重组对照通过。短录像和完整录像均有恢复后的续建；大地图原录像中断，结果明确按中断保存处理。按原速单独写盘 1,581 帧没有发生队列满等待。详细耗时与证据边界见 [v30 离线记录](offline_v30/README.md)，不能据此宣称真实并发采集卡顿已解决。
