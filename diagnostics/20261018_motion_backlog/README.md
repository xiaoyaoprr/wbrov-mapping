## 对修复方向的约束

用户要求保持地图质量，允许延迟，持续记录后按顺序慢处理。现有候选只实现原始录制，**没有实现自动后台追赶建图**。

1. 把原始采集、实时定位、延迟建图拆开。优先保留原始双目与 IMU、源时间、标定和帧索引；固定低频主图抽帧不能作为唯一可恢复历史。
2. 后台消费有序、可重试的帧段。采用完成回执推进游标，不能计算不过来便覆盖中间帧。队列应落盘并有容量、失败与积压统计；不能承诺有限硬盘无限录制。
3. 首先使用真实失败录制做相同几何阈值下的密集帧处理对照。记录缺帧、可用深度、姿态连续性、真实几何内点和最终轨迹一致性；2D 特征匹配或慢放成功不算地图验证。
4. 过去帧使用记录时的源时间及完整 IMU 对齐。后台时钟用于调度，不冒充实时传感器时钟；过期位姿不进入实时定位或控制通道。
5. 实时质量不足可冻结主图提交，但不终止原始录制或清空待处理历史。优先检查失锁前后密集帧能否重建连续链，再进行主图对齐；不能把一次稀疏旧图匹配失败等同于整段高频局部估计已断裂。
6. 后台轨迹、几何和锚定通过后提交对应点云。无法约束的段保留原始记录及独立子图，不能为了补满把它假定到主图原点或失锁前位置。
7. 界面分别显示实时画面/定位、原始录制状态、已验证地图的源时间、积压时长及失败原因。旧点云可以保留显示，不能包装成当前位置实时更新。
8. 不降低内点、空间覆盖、退化方向、重力和跨图一致性门槛来通过演示。曝光模糊、无共视和采集缺帧须如实报告；延迟增加算力预算，不能生成不存在的测量。

这份记录是故障证据与实现约束，不是后台补算功能完成声明。遮挡/不同视角恢复、后续持续写入和整体正常保存退出仍须重新验收后才能更新生产入口。
