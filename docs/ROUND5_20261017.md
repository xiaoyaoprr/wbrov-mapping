## 修改边界

1. **候选与节点同步失效。** 在 Core 最终确定 `signaturesRemoved` 后，清除任一端点已移出内存的跨图候选。节点删除、receipt 清理、候选清理使用同一轮 `process()` 的结果，不把已删除节点作为恢复证据。
2. **允许最近候选稍早于当前帧。** 最新候选必须仍有 Signature 和同来源 receipt，与当前节点同 epoch / map，源时间差不超过 6 秒。此检查只允许进入核验；从最早桥端点到当前节点的完整保留后缀仍逐边认证，不能跳过中间节点或猜测邻边。
3. **当前重定位与历史回填分开。** 只有 prepare + 五次独立主图观察 + observed commit 路径采用 `CurrentReanchor`。注册集合 R 是最早桥端点至最新节点之间的全部保留节点，上限 32；旧 immediate/full-segment API 仍检查整段历史。三桥、双向原始几何、交叉留一验证、信息矩阵、运动一致性、旧主图位姿不动及提交前新鲜度检查保留。
4. **历史前缀不能被连带提升。** R 之外的前缀保留原有节点、map ID、epoch 和 receipt，提交时解除前缀与 R 的实际 Memory 边；优化、正常回环、可信图、显示分别排除前缀。前缀内部不连通的部分分别归一化到独立局部原点。没有伪造新 epoch 或改写观测身份。
5. **短恢复段使用明确的重力证据契约。** 旧整段路径仍要求至少 10 节点 / 15 秒及原重力覆盖率。新的当前重定位路径要求 3–32 个后缀节点、源跨度至少 0.2 秒、每个节点都有实测重力，再通过相同重力残差限值和后续五次旧图观察。旧时间长度代理不能直接套到三个桥视角组成的短段；该变化不豁免原始几何或观察期。
6. **Tag 历史参考按节点存在性筛选。** “这个 epoch 曾经提交”不足以授权该 epoch 内所有节点。候选、缓存参考和历史保留都检查节点是否还在经认证的 Core 图快照中；被隔离前缀不能作为主图参考，也不能因缺失 pose 使恢复消费者退出。已在较早快照出现、随后被新快照移除的帧会明确结束 ready 等待；尚未见过的未来节点仍等待，不能把 DDS 到达顺序差异当成删除。
7. **历史显示避免反复解压。** 已发布且未变化的非活动子图保留小型位姿指纹，释放体素缓存；其 latched 点云无需随每次主图更新重新解压和组装。节点集合或位姿变化时完整重建。

双向配准使用同一对图像和深度，其一致性不等于两路独立传感器证据，不能据此判断它或原里程计哪一个是真值。跨候选局部词 ID 的 Jaccard 不参与 guard 验证；不同节点、分离视角和分离源时间承担观测独立性检查。
