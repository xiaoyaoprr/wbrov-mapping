## 已采纳的核对结论

连续性门接收的是全速 OdomInfo，不能用 1 Hz 建图节拍解释其时间门。
300 ms 源间隔和 750 ms 已测量桥接上限保持不变；连续弱观测预算仍为
500 ms，整个核验窗口为 6 s，不随弱/好交替延长。资格门比例降为 0.15，
正常几何认证比例仍为 0.25，恢复认证仍为 0.35。

移除只有已注册主图才能进入质量核验窗口的限制。未注册子图使用同 epoch
的两个独立原始 RGB-D 参考进行只读核验，通过后只能继续写该独立子图。
它不会因此变成主图。真实 lost、未认证源间隔、坏几何及超时仍会切链。

到达延迟和消息间隔分开检查：单包到达延迟最多 300 ms，距最近到达最多
300 ms。当前导航位姿输出仍要求源时间年龄不超过 300 ms；地图门限的拆分
不会让旧定位获得实时控制资格。

只因收包延迟或同一有界窗口暂停时保留候选票据身份，但清空观察计数；仍需
重新完成独立观察。真实切链、epoch/图版本变化和候选拒绝会使票据失效。
候选提交后清除质量窗口，避免已恢复主图被旧窗口再次暂停。

跨图视觉候选改为从原始 RGB-D 重新提取特征，内点 ID 只在本次配准修改过的
两个局部 Signature 内查找，不再拿局部词典 ID 查询持久词典。
最终双向几何复验、整段认证、图优化和提交前校验保持启用。

Tag 确认间隔按配置的输入周期确定，兼容 1 Hz；仍要求三个不同观测。
漏检会失效，重复时间戳不会增加确认数。按用户决定，本轮不实现临时子图
之间互连，也不绕过旧 epoch 的在线合并限制。

可信参考图按新图像更新并使用保留发布，RViz 晚启动也能收到。它不再依赖
恢复票据代数变化，否则 generation=0 或收包暂停保留代数时会一直显示 No Image。

## 录制及保存

默认双流相机发布器在 IMU/深度/建图筛选之前启动 SVO2 录制；保存 SDK 版本、
外部标定、SDK 初始化/运行配置、相机 IMU 外参及源时间记录。SVO 保存立体图像
与 SDK 传感器数据，不保存计算得到的深度。压缩采用 H265，并非像素无损存储。
只称为 SDK 已接收帧覆盖，不承诺
传感器零丢帧。磁盘保留 2 GiB，录制错误不能被“正常关闭”掩盖。
显式选择的旧相机回退 profile 不支持新录制能力；报告标记未录制，不把它称为
完整 SVO，也不因缺少这项能力破坏该 profile 原有的地图保存。

关闭后核对录制状态、文件哈希、SVO 索引帧数和首末帧解码。逐帧解码单独验收。
`tools/verify_raw_recording.py` 的 `--replay-calibration`、`--replay-init`、
`--replay-runtime` 必须同时提供，并与记录时的哈希一致；SDK 版本也必须一致。
该命令只验证离线输入契约，不代表已经重建地图。

完整主图导出 `rtabmap_dense.ply`。若还存在未对齐分量，则主图导出为
`rtabmap_partial_main.ply`；`submaps.json` 记录各分量节点和独立坐标，原始 RGB-D
保留在关闭后的数据库中。子图坐标来自保存的局部里程计，不能称为已全局优化。
`save_report.json` 分别报告原始录制、主图导出和子图归档。归档完整不授予自动续建
权限；未完成主图覆盖的数据库不列入 2 号自动续建候选。
