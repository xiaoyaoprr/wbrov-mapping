## 已部署修复

`MappingContinuityGate` 将消息新鲜度与局部坐标连续性分开：计时器过期、连续源序列中的健康但延迟消息仍暂停写入并撤销在途凭据，但不单凭接收延迟断开局部图。超过 300 毫秒的源时间空档、未来时间戳、lost 或几何失效仍断开局部图。300 毫秒新鲜度阈值不变；主图恢复仍须通过五次独立几何观察，临时图不因此获得主图注册资格。

新增状态机回归在 Jetson 上复现旧头文件的错误，新头文件通过全部断言。随后原生重编译 `librtabmap_slam_plugins.so` 和 `rtabmap`；编译依赖记录确认实际使用修复头文件。三组门控测试通过，实际 ROS Wrapper 的 100 毫秒定时器测试通过：过期后禁止主图写入、撤销旧凭据，随后源时间相隔 183 毫秒的健康消息不增加局部连续性序号。测试还保留真实失锁、几何失效、IMU-only 暂停和主图恢复观察期检查。

测试夹具最初只发布状态快照，未执行定时器，新增凭据检查失败；改为运行真实 ROS 定时器后通过。此处只修正了测试调用，生产修复未因此放宽门控。

已生成新的独立运行包，通过全树、动态依赖、入口和安装后只读检查，再切换 8 号两层脚本。详见 [验证回执](../provenance/submap-tag-20261015/receipt-expiry-check.json) 和 [部署与回退](DEPLOYMENT_20261015.md)。上述编译、回归和文件部署阶段没有重新运行完整图像录像回放，也没有启动相机、遥控或灯光。之后用户再次启动遇到 Argus 残留占用，已另行恢复空闲相机服务并验证两次相机开流、关闭和重开，见部署记录；这些验证均不能作为水下连续建图已验收的证明。
