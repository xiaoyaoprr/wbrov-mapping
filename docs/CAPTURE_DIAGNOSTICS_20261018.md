# 采集线程诊断日志等待修复（候选）

上一轮静止实机的最慢里程计样本延迟为 575 ms，同一时段采集线程在同步计划日志调用内等待 483 ms。配准本身约 20 ms。日志调用等待的底层原因尚未确认，但不应让它阻塞下一次采集。

本次将相机进程的应用诊断消息交给独立线程写入 ROS 日志。采集线程只格式化有大小上限的记录并入队；队列最多 2,048 条，写入线程持有输出接口时不占队列锁。记录保留原有事件、序号和源时间，新增 `diagnostic_enqueued_steady_ns` 区分入队时间与实际打印时间。测量、里程计 ACK、录制日志、恢复门限和图状态均不使用这条诊断队列。

溢出、超长消息或输出异常会计数，退出时输出 `ASYNC_DIAGNOSTICS` 完整性回执；不完整返回非零退出码，实机验收也必须检查该回执。正常退出会排空已接受的诊断记录。若底层输出永久阻塞，排空仍可能等待；本改动只隔离运行期间采集路径，并不承诺输出设备永久故障时的有界关闭。

Jetson 原生编译与动态链接检查通过，11 项 CTest 通过。新增测试让输出端持续阻塞，验证生产者能够在释放输出端前完成；另外覆盖队列满、按序排空、消息过长和输出异常。
