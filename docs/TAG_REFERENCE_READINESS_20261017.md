# Tag 参考资格与角度间隔复核

本次复核针对本地 round5 候选代码；不把旧版本行号当作当前实现证明。

## 已确认的约束

- `acceptCrossMapLoopEvidence()` 使用 `current.getPose() * currentToOld * old.getPose().inverse()` 比较主图到当前局部坐标的变换。它不要求当前相机与历史相机处于同一位置或角度。
- 每一对当前候选的平移至少 3 cm 或旋转至少 3°；这两项不是必须同时满足。guard 模式下每个 oldId 至多保留一个候选，三个候选必须来自不同旧节点和不同当前节点。
- 在线 Tag 路径为 `runtime/libexec/wbrov_corner_recovery/measured_bridge.py` 的 `best_old_triplet()`。它在旧图和当前图分别要求三组独立视角，旧侧还须有一致的平面分支。`src/apriltag/build_apriltag_multiview_anchors.py` 是保存后锚点构建路径，也要求至少三个不同 saved-node，不能把它误认为唯一在线确认器。
- 三个不同节点是必要条件，不是充分条件。相同姿态的重复帧可减少部分随机噪声，却不能替代这里要求的视角多样性；同一相机的多视角仍不是三个独立传感器，也不能消除共同的标定偏差。
- `CrossMapLoopMaxFeatureJaccard` 已被参数说明标为兼容保留的诊断量，当前代码没有使用它拒绝证据。round5 停止比较不同局部词典的数值 ID，没有删除一条原有验收条件。

主图只留下某 Tag 的 1–2 个可用节点时，失锁后移动相机不能补足该 Tag 的历史参考。此结论限于该 Tag 三桥路径；不等于其他 Tag 或原生旧关键帧恢复也必定不可用。旧节点退休、隔离前缀或缺失原始证据同样会使历史参考失效，不能只数台账总行数。

`custom_20261010_043206` 和 `custom_20261010_050110` 没有这种原生拒绝。扫描仅统计已记录的原生候选拒绝，不代表 Python 三视角组合枚举里所有未入选组合的数量。完整计数和日志哈希见 `diagnostics/20261017_tag_reference/view_spacing_audit.json`。该间隙实际影响过筛选，但不能解释最近的观察期超时或恢复后冻结边界冲突，也不代表非相邻节点无法组成三视角。

## 待实现的操作员提示与采样策略

应分别显示：主图中仍有效的不同参考节点数、是否选出独立且一致的三视角、当前恢复阶段及具体拒绝原因。例如“Tag 8：主图参考 2 个，尚缺独立视角”；达到三个节点后仍需明确几何是否通过，不直接显示“可恢复”。最后可信图像只提供相近视野提示，不能暗示回到一张图就满足三桥条件。

采样应以参考覆盖为目标，并受位姿质量和负载限制；简单降低 LinearUpdate/AngularUpdate 会增加近重复帧，不能保证独立性。先观察现有节点间的实际间隔、参考淘汰和检测绑定，再决定是否在 Tag 可见且跟踪健康时主动补充关键帧。本次未降低恢复独立性或几何阈值，未实现自动降低关键帧门限。实机测试先用只读诊断选择器确认三组有效主图参考，再让操作员遮挡。
