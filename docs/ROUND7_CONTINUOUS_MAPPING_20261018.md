## 数据路径

1. 相机维持连续 SVO 编码，不通过每秒关闭、重开 SVO 来生成处理片段。原先尝试的 SDK 分段录制会产生轮转间隙，未启用。
2. `rgbd_spool.hpp` 的采集侧只复制一帧数据并送入有界队列；磁盘线程封存约一秒源时间的数据包。临时文件不会被处理器当成有效输入。队列满、磁盘空间不足或写入错误明确报告，不静默丢弃已接受的数据。
3. `deferred_mapping.py` 验证序号、严格递增的源时间、配置与文件哈希。后台里程计和 Core 在独立线程中有序工作；仅在整段完成并再次校验后确认该段。
4. 门控使用录像的原始时钟，保留几何、协方差、弱帧窗口、跨图三桥及后续五次观测条件。未对齐子图不会进入主图点云。录像位姿不发布为当前导航 TF。
5. 相机退出后，处理器排空输入，关闭数据库，保存点云和校验回执。失败时保留原始输入及未完成输出；重启处理需要新目录，从首段重建内部状态。

低分辨率观测按采集实际产生的每个唯一时间戳保存；高分辨率 RGB-D 约 5 Hz 保存。全分辨率原始立体图像另外存入连续 SVO。新候选 RGB-D 队列采用逐帧无损编码，旧格式仍可读取；原始未压缩记录约 2.2 GB/分钟。所有已接受记录均保留，不等于传感器所有曝光都被无损采集；写盘等待仍可能阻止下一次抓取。

## 界面补充与性能工作

- 用 Core 门控字段明确区分建图中、主图暂停、恢复核验中、失败和已保存；采集状态与待处理时长单独显示。
- Tag 标注由已保存深度中的位置产生，显示编号与独立参考数量；标记仅用于显示，不作为额外合并证据。
- 青色历史轨迹只连接主图内已验证的同 epoch 邻接边；跨失锁段不画推测直线。最新显示已按用户要求把橙色箭头改为红 X／绿 Y／蓝 Z 三轴，仍代表最后可信记录位姿，不是当前导航位置。
- 对单节点点云增加有界缓存；优化位姿、源时间或像素身份变化就重算。缓存淘汰只导致重算，不删地图点。
- 当旧节点身份、位姿完全不变且只追加更大 ID 的节点时，可增量扩展已组装点云。旧位姿/像素改变、节点移除或插入更小 ID 均全量重组，保留相同体素碰撞优先级。原生对照测试覆盖这些情况以及组装失败时保留先前输出；该优化的实测收益有限。
- 后台预读最多一个已封存 RGB-D 片段，让读取、哈希与 Tag 检测和当前段原生处理重叠。SVO/SDK 校验仍串行。预读完成不推进处理回执。
- OpenCV 线程预算显式记录在会话身份中，默认 1；2/4 线程仅在对照测试中使用。没有降低内点、覆盖、协方差或恢复门槛。
- 新增阶段耗时：里程计估计/局部束调整、Core 处理、已合并图检查、恢复观测、Tag 候选和两项导出。子阶段互有包含，不能直接相加当作总墙钟耗时。

## 吞吐优化的第二组对照

用户选择先缩短延迟、再切换 8 号。本组仍只运行隔离候选，未改生产入口。优化没有跳过录像中的里程计帧，也没有降低恢复几何门槛：

1. 点云缓存额外保存相机坐标下的采样点。优化只改变节点的世界位姿时，不重复解压同一份 RGB-D。体素查找使用哈希表，最终仍按原有体素键排序导出；碰撞仍由较小节点 ID、较早采样像素获胜。
2. 主图健康时，在每帧里程计和门控之后，推迟既无新 Tag、又无足够累计位移/转角的重复 Core 调用。累计运动基于上一个实际接受的节点，超过一秒仍调用；退化、恢复核验和未注册子图保持原有处理路径。它没有降低 Core 自身的节点接纳门槛。
3. 原生里程计最多预处理下一个已封存片段。预处理结果不是写图回执；下一段 Core 写入仍须等上段精确 ACK 和输出哈希检查完成。输入身份变化、数据哈希变化或遗漏预处理段直接关闭均须报错。
4. 核对实际编译命令发现，三个自定义 Core 单元的历史命令末尾有 `-O1`，覆盖了前面的 Release 标记。以完全相同源码重新编译为 `-O3`，未启用 `fast-math`。原生 Core/Wrapper 回归通过；Wrapper 首次缺少 AMENT 环境的失败及补齐环境后的结果均保留。

## 校验范围

用户进一步明确：所有采集帧都必须在线处理，不接受静止/低运动时挑代表帧。后续优化只针对等价计算、缓存、内存与流水线，逐帧里程计与质量检查保持完整。地图关键帧仍按已有质量和运动条件接纳；这与丢弃里程计输入帧不同。

新增投影匹配优化只处理二进制描述子：沿用同一投影半径搜索结果及其顺序，直接计算 Hamming 距离，避免逐个特征复制候选矩阵、构建 BFMatcher。保留首个最小距离、相同的浮点 NNDR 比较、单候选行为和单查询交叉检查。浮点描述子保持原路径。Jetson 上 48,000 组随机、重复候选、相同距离、非连续内存测试与原 BFMatcher 选择相同；30,000 次微基准为原路径 294.037 毫秒、直接计算 18.595 毫秒。微基准不代表整条链路提速比例。

该版本的 Core、候选生命周期、Tag、门控和 Wrapper 原生测试均通过。v24 短录像完整处理 1,581 帧并完成一次恢复，最终 NORMAL、99 个主图节点、97,648 点；耗时 119.783 秒，里程计为 63.828 秒，Core 为 60.416 秒。里程计阶段降低，但总耗时未比 v18 更短；完整现场录像结果另行审计，未据微基准更新生产入口。
