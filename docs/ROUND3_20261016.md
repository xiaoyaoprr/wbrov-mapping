# 第三轮：短暂退化先停写，再验证原主图

这次修改针对“里程计仍返回位姿，但几何质量瞬间不合格就立即切段”的路径。之前一次现场首切窗口内 `lost=false`，最低内点数39；已有日志不足以确定当帧究竟是空间分布还是协方差触发，不能把所有切段都判成误判。

## 状态机变化

- 已接入主图时，若仍有有限位姿、正定协方差、正确图像尺寸及实际配准支持，但完整几何质量不合格：立即停止主图和局部图写入，保留冻结主图参考，进入有期限的核验。
- 弱质量最多等待500毫秒恢复。恢复后仍不允许仅凭健康里程计直接续写；整个核验最多6秒，重复弱帧和回执刷新不能延长期限。
- 使用现有Core原始RGB-D旧图验证：至少两份旧关键帧证据，按原几何及修正量限制完成5次独立主图观察。通过后从下一张合格帧继续写入；弱质量段不回填。
- 核验失败、超时，或出现明确失锁、非有限位姿、无效协方差、错误尺寸、没有实际配准支持时，切断局部连续性，后续可信局部数据只能进入独立的未对齐子图。
- 回执迟到恢复与几何质量退化分开处理。短暂弱几何不能使用 `resumeContinuousReceipt()` 绕过旧图验证。既有源时间新鲜度、测量间隔和过期事务门保持有效。

这保留的是“待核验的原坐标关系”，不宣称退化期间的位姿可信。长时间无法重定位时仍需临时子图；不能通过扩大预算或把IMU平移预测当测量来消除地图断点。

## 诊断与显示

状态增加有限位姿、协方差正定/范围、图像尺寸、当前质量原因、首次退化原因、最近切段原因/源时间/计数。原因包含实际网格占用、分布指标或超界协方差值。诊断中的切段计数是门控失效次数，不等于已经写出点云的子图数量。

已有被动位姿诊断记录状态变化，保留触发时的值。该诊断依旧只是旁路观察，不将DDS端点快照声称为逐条消息身份认证。

RViz增加固定的 `Mapping_Status_建图状态` 图像面板，显示主图写入状态、未对齐子图数量、观察进度及原因。原中文三维文字继续保留。过期状态或不匹配的会话显示连接待检查，不能保留绿色建图状态。未对齐点云继续使用自身坐标系和独立视图。

## 对第三轮意见的取舍

1. 不采用“有有限位姿就视为连续”的自动放行。有限和正定只够进入待核验窗口，不能证明跨过了弱几何区间。
2. 不存在生产配置下“1–14个视觉内点仍成功”的已证实死区：生产 `Vis/MinInliers=15`，F2M在后续优化内点不足时也会返回空位姿。本次实际首切窗口最低39个，新增诊断用于定位真正原因。
3. 不扩展深度测量间隔桥接。当前只保留已有认证F2M视觉间隔路径，深度端点及连续区间证据尚未验证。
4. 入口显式固定候选协方差下限：`CrossMapLoopMinLinearSigma=0.02`、`CrossMapLoopMinAngularSigma=3.0`。这与已部署Core默认值一致，不放宽最终恢复事务。
5. 无Tag完整恢复仍是在线验收项，不能改名为离线任务来消除未通过状态。当前未实现全程SVO录制，不宣称已经具备这项能力。

### 首次真实相机检查未通过（保留历史结果）

候选窗口在36.4秒可见；45秒观察中取得890个实时图像时间戳、889个单帧点云时间戳和181个固定状态图像时间戳。相机健康检查记录有效里程计19.35Hz，但主图写入许可为0，未收到`/cloud_map`。

新诊断显示主要是 `visual=cells=5<6`，部分帧为3或4格。短暂退化确实进入了新限时路径，随后因弱质量持续而切段。实际图像显示反光箱壁、箱沿和地面；不能把持续覆盖不足当成可信连续位姿，也没有降低6格门槛。随后用户调整静止场景；复测结果见下节，未降低门槛。

RViz同时报 `Failed to create an OpenGL context. GLXBadDrawable`，截图全黑；这是与DDS有图像/点云消息分开的显示故障。随后在不启动硬件的隔离ROS域中，旧版两图像面板一次、新版三图像面板两次均无GLX错误并能渲染，**不能据此宣布真实负载下的偶发黑屏已修复**。上游也有[同类Jetson报告](https://github.com/ros2/rviz/issues/1314)，仅作调查线索，未据此更新系统Ogre或驱动。

正常关窗后数据库保留17个节点，但注册主图仅有1个已保存优化位姿，其他隔离分量未覆盖，因此导出校验拒绝整轮成功、退出码为1；数据库和诊断完整保留。此结果不是保存成功，不能发放正常续建回执。此前长任务 `custom_20261009_040556` 的类似保存失败也未改写成成功。

按既有授权只使用30%双灯，灯光发送器仅允许心跳和灯光包，未发送运动或解锁。首次测试结束灯光正常关闭，建图/相机进程退出，UDP3333释放；当时未切换8号。
